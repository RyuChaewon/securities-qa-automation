# 1Q HTS ChatGPT 시나리오 생성 패키지

## 사용 방법

1. ChatGPT 새 대화에 이 폴더의 `01_ChatGPT_요청문.md`부터 `07_오류_판정_정책.md`까지 7개 파일을 첨부한다.
2. `01_ChatGPT_요청문.md`의 내용을 그대로 요청문으로 사용한다.
3. ChatGPT가 만든 `generated-scenarios.json`을 `05_생성결과.schema.json`과 로컬 검증기로 검사한다.
4. `datasetPatch.variables`는 검토 후 기존 `data/rule-tests/account-info-07.dataset.json`의 `variables[]`에 병합한다.
5. `locatorRequests`가 남은 컨트롤은 화면 표시문자 또는 실제 런타임 결합 정보를 확보하기 전까지 실행 데이터로 확정하지 않는다.

## 파일 설명

- `01_ChatGPT_요청문.md`: 바로 사용할 요청문
- `02_화면_시나리오_컨텍스트.json`: 14개 화면의 압축된 기준 모델
- `03_공통_테스트데이터_사전.json`: 공식 입력값·종목 표본·오류코드
- `04_데이터셋_작성_계약.json`: 실행기 데이터 구조와 생성 규칙
- `05_생성결과.schema.json`: ChatGPT 산출물 검증 스키마
- `06_생성결과_예시.json`: 형식 예시
- `07_오류_판정_정책.md`: PASS·FAIL·PENDING 기준
- `08_생성결과_검증.mjs`: 화면·컨트롤·검증규칙·민감키 검사
- `PACKAGE_MANIFEST.json`: 파일 해시와 출처 지문

## 중요한 제한

- 이 패키지에는 계좌번호·예금주·비밀번호·로그 원문·스크린샷·좌표가 없다.
- MAP은 정적 정의이며 실제 활성 상태와 탭 순서는 실행 시 다시 확인한다.
- 과거 런타임 관찰은 MAP과 일대일 결합되지 않은 보조 근거다.
- 업무 결과 수치의 기대값은 별도 업무 데이터가 없으면 생성하지 않는다.
- 생성 결과는 바로 실제 HTS에 적용하지 말고 스키마 검증과 사람 검토를 거친다.

## 생성 결과 검사

ChatGPT가 만든 파일을 이 폴더에 `generated-scenarios.json`으로 둔 뒤 실행한다.

```powershell
node .\08_생성결과_검증.mjs .\generated-scenarios.json
```
